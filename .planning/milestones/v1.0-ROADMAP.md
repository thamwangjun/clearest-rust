## Milestone Summary

**Key Decisions:**
- Minimal v1 roadmap (single-bug-fix scope) — feature parity is largely achieved; new Claude Code features arrive as new milestones
- `spec/` as parity ground truth — 990 KB across 15 files, reverse-engineered from the official TypeScript Claude Code
- D-04 scope change: `use_bearer_auth` removed rather than exposed; `deny_unknown_fields` added (user-approved in UAT Round 2)
- TDD with `serial_test` to prevent env-var race conditions in async tests
- `auth_status()` conflict check intentionally mirrors resolver D-02 condition rather than delegating (minimal fix scope; documented as tech debt)

**Issues Resolved:**
- BUG-01: Welcome screen silent exit on Enter keypress
- Collapsed thinking block content leak in TUI rendering
- First-run startup routing landing on ProviderSetup instead of Welcome
- ANTHROPIC_AUTH_TOKEN not accepted as a valid credential source
- UTF-8 byte-boundary panics in bridge error truncation and TUI prompt truncation
- Dead `_http` parameter in `start_bridge_with_client`
- Duplicate CLAUDE_ORANGE / BRAND_PINK color constant

**Issues Deferred:**
- BUGS-01 through BUGS-05: Mouse capture, Ollama routing, API key paste, keyboard layouts, voice mode
- FEAT-01: Managed Agents (plan.md architecture)
- FEAT-02: MCP security hardening (#123)
- FEAT-03: Ongoing upstream Claude Code feature sync

**Technical Debt Incurred:**
- `RenderContext::default()` in `lib.rs` test render paths (lines 1009, 1029) uses `frame_count=0` — collapsed thinking blocks in those paths always show one dot (not production)
- `auth_status()` conflict check mirrors resolver D-02 condition 1 rather than delegating — future additions to `resolve_anthropic_auth_async` conflict logic must be manually mirrored
