<objective>
Fix the `/status` slash command and the `auth_status()` CLI function to correctly
reflect bearer token authentication.

When `ANTHROPIC_AUTH_TOKEN` is set, both display paths currently show "Not
authenticated" because they only consult `resolve_api_key()` /
`api_key_env_vars_for_provider()`, neither of which knows about bearer tokens.

Purpose: Close the UAT gap — authenticated users with ANTHROPIC_AUTH_TOKEN see a
misleading "Not authenticated" status instead of the correct "Authenticated (Bearer
token)" label.

Output: Two surgical edits — one in `crates/commands/src/lib.rs` and one in
`crates/cli/src/main.rs`. No resolver logic changes. No new public API surface.
</objective>

let auth_status = match ctx.config.resolve_anthropic_auth_async().await {

bearer-mode OAuth and `Ok(Some((key, false)))` for managed-key OAuth, which maps cleanly
to the labels above.

Note: `resolve_api_key()` was the sync fallback that only checked `ANTHROPIC_API_KEY`.
Do NOT keep that call — the async resolver replaces it entirely.

In `crates/cli/src/main.rs`, locate `async fn auth_status` (around line 3313).

The `env_api_key_source` binding at line 3328 only iterates `api_key_env_vars_for_provider(active_provider)`,
which returns `["ANTHROPIC_API_KEY"]` for Anthropic — `ANTHROPIC_AUTH_TOKEN` is never
checked.

Add an explicit fallback for `ANTHROPIC_AUTH_TOKEN` **after** the existing
`env_api_key_source` binding, so the bearer token env var is treated as a valid key
source when the active provider is Anthropic:

```rust
// Existing binding (do not change):
let env_api_key_source = claurst_core::config::api_key_env_vars_for_provider(active_provider)
    .iter()
    .find_map(|env_var| {
        std::env::var(env_var)
            .ok()
            .filter(|value| !value.is_empty())
            .map(|_| (*env_var).to_string())
    });

// ADD immediately after — before `stored_api_key_source`:
let env_api_key_source = if env_api_key_source.is_none() && active_provider == "anthropic" {
    std::env::var("ANTHROPIC_AUTH_TOKEN")
        .ok()
        .filter(|v| !v.is_empty())
        .map(|_| "ANTHROPIC_AUTH_TOKEN".to_string())
} else {
    env_api_key_source
};
```

This shadows the original `env_api_key_source` with the bearer fallback when no
standard API key env var was found. The rest of `auth_status()` uses `env_api_key_source`
opaquely — no further changes needed. The displayed source string "ANTHROPIC_AUTH_TOKEN"
is self-explanatory in the "API key:" line of human output.

Do NOT modify `api_key_env_vars_for_provider` itself — that function is used in other
contexts where bearer tokens must not appear.
