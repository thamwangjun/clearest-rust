<objective>
Fix the welcome dialog startup routing bug (Bug 2 from Phase 1 UAT) and add a regression test.

`main.rs:1435` incorrectly calls `app.onboarding_dialog.show_provider_setup()` for first-run
no-credentials users. `show_provider_setup()` sets `page = OnboardingPage::ProviderSetup`, so users
skip the Welcome page entirely and land on the provider setup screen. The correct method is `show()`,
which sets `page = OnboardingPage::Welcome`.

Fix: Change one method name on one line. Add a test file that calls `show()` directly and
asserts `visible=true, page=Welcome`.

Purpose: D-04 and D-07 — targeted one-word fix with regression test coverage.
Output: Modified `main.rs`, new `crates/tui/tests/startup_routing.rs`.

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum OnboardingPage {
    #[default]
    ProviderSetup,
    Welcome,
    KeyBindings,
    Done,
}

#[derive(Debug, Default, Clone)]
pub struct OnboardingDialogState {
    pub visible: bool,
    pub page: OnboardingPage,
}

impl OnboardingDialogState {
    pub fn show(&mut self) {
        self.visible = true;
        self.page = OnboardingPage::Welcome;  // correct starting page
    }

    pub fn show_provider_setup(&mut self) {
        self.visible = true;
        self.page = OnboardingPage::ProviderSetup;  // was incorrectly used at main.rs:1435
    }
}
```
